# NXTCORE

Дневник, в котором день из текста, фото и песни становится небольшим воспоминанием. Вы пишете пару строк, добавляете снимки и ссылку на песню, а NXTCORE оформляет всё в открытку с движением: фото сменяют друг друга в темпе песни, цвета берутся из настроения дня, внизу появляется название и ваша подпись. Готовые дни лежат в архиве папками.

Сайт сделан на чистых HTML, CSS и JavaScript, без фреймворков. Данные, вход и файлы живут в Supabase, фото проверяет Gemini. Деплой: GitHub и Vercel.

Проект сделан для хакатона REC Genesis, кейс ArtTech «Make the Invisible Visible». Как устроена визуальная система и почему она узнаваема в серии, описано в [docs/VISUAL-SYSTEM.md](docs/VISUAL-SYSTEM.md).

## Что умеет

- Регистрация по почте с обязательным согласием на политику конфиденциальности, вход, Google OAuth.
- Профиль: аватар с проверкой на запрещённое, никнейм с проверкой «✓ свободен / ✗ занят» на лету, имя, описание до 150 символов, счётчики записей и лайков, кнопка «Настройки» (язык, тема, видимость по умолчанию, озвучка, ИИ).
- Записи: текст до 1000 символов, до 6 фото, настроение, песня (ссылка, поля вручную или свой файл), погода по желанию, личная или публичная. Можно изменять и удалять, у изменённых стоит отметка «изменено».
- Лента: подборка из 100 записей собирается заново, когда заканчивается, внутри подборки новые выше. Записи заблокированных авторов скрыты. Если записей нет, видно только «Пока постов нет...».
- Лайки без задержки в интерфейсе, комментарии, уведомления (лайк, комментарий, подписка) с бейджем в шапке, поиск по людям и записям.
- Архив: дни лежат папками по месяцам, есть фильтр по настроению.
- Модерация: ники, тексты и фото. Нарушения копятся: предупреждение, блокировка записи на 24 часа, бан. Жалобы на записи и профили, три жалобы от разных людей прячут запись.
- Русский и казахский интерфейс, светлая и тёмная тема, адаптив 768/480.
- Политика конфиденциальности на двух языках на странице `/privacy`.

## ИИ-помощник

Работает через Edge Function `ai`. Ключ Gemini лежит только в Supabase, в браузер он не попадает.

- «Описание по фото»: коротко описывает снимки и дописывает в запись.
- «Шаблон и песни по описанию»: разбирает текст, предлагает название и три песни, подстраивает оформление.
- «Всё вместе»: оба шага подряд.
- Проверка фото на запрещённое обязательна и в настройках не отключается. Если ИИ недоступен, фото не сохраняется (поведение меняется переменной `MODERATION_FAIL_OPEN`).

Без ИИ сайт тоже работает: текст разбирается локальным словарём, название собирается правилами, темп песни берётся по жанру или из вашего файла.

## Структура

```
index.html              одна страница, всё остальное подключается модулями
vercel.json             перенаправление на index.html, заголовки безопасности, CSP

js/core/                роутер, оболочка, API, состояние, DOM-хелпер, иконки, интерфейсные мелочи
js/i18n/                словари ru и kk
js/memory/              движок воспоминаний: цвет, анализ текста и музыки, рендер на canvas
js/moderation/          проверка слов в браузере (подсказка, решает база)
js/pages/               страницы
supabase/sql/           01 схема, 02 модерация, 03 RLS, 04 триггеры, 05 RPC, 06 хранилище, 07 стоп-слова
supabase/all.sql        всё вместе, собирается `npm run sql`
supabase/functions/ai/  Edge Function (Gemini)

docs/SETUP.md           пошаговая настройка
tests/                  проверки движка, SQL, Edge Function и интерфейса
```

## Быстрый старт

Подробно со всеми кнопками: [docs/SETUP.md](docs/SETUP.md). Коротко:

1. Создайте проект в Supabase и выполните `supabase/all.sql` в SQL Editor.
2. Впишите `SUPABASE_URL` и `SUPABASE_ANON_KEY` в `js/config.js`. Это публичный ключ, права ограничены политиками RLS.
3. Задайте секрет `GEMINI_API_KEY` и задеплойте функцию: `supabase functions deploy ai`.
4. Запустите локально: `node scripts/dev-server.mjs` и откройте http://localhost:5173.
5. Залейте репозиторий на GitHub и подключите к Vercel (без команды сборки, корень проекта).

## Переменные окружения

В браузерный код секреты не попадают. Всё секретное хранится в Supabase.

| Переменная | Где | Зачем |
|---|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | `js/config.js` | адрес проекта и публичный ключ |
| `GEMINI_API_KEY` | секрет функции | вызовы Gemini |
| `GEMINI_MODELS` | секрет функции, необязательно | цепочка моделей по порядку |
| `ALLOWED_ORIGIN` | секрет функции, необязательно | адрес сайта для CORS |
| `MODERATION_FAIL_OPEN` | секрет функции, необязательно | `true` пропускает фото при сбое ИИ |

Шаблон лежит в `.env.example`. Файлы `.env` в репозиторий не попадают (см. `.gitignore`).

## Как устроена защита

- Все записи в базу идут через функции с `security definer`. Прямая вставка и правка постов, комментариев и профилей закрыта правами.
- Поля бана, страйков и мута не читаются с клиента. Свой полный профиль отдаёт `my_profile()`.
- Загрузка фото возможна только через Edge Function: сначала проверка Gemini, потом сохранение. Обойти проверку с клиента нельзя.
- Приватные файлы (`photos`, `audio`) отдаются по подписанным ссылкам. Свой аудиофайл слышит только автор.
- Проверка слов в браузере служит подсказкой до отправки. Окончательное решение принимает база.
- Блокировка закрывает сессии аккаунта, заблокированный не может писать, а его записи и комментарии скрыты.

## Проверки

```
npm run test:engine   # движок воспоминаний, музыка, заголовки, модерация (20 проверок)
npm run test:edge     # Edge Function с подменой Gemini и Storage
npm run test:i18n     # все ключи есть в ru и kk
npm run test:sql      # схема, RLS, триггеры, страйки на локальном Postgres (см. tests/run-sql.sh)
npm run test:ui       # сквозной прогон в headless Chrome, нужен playwright и запущенный dev-сервер
```

Интерфейс проверяется с подменой supabase-js, поэтому с настоящим проектом Supabase и настоящим Gemini его нужно один раз пройти руками: регистрация, Google, загрузка фото, ИИ, бан. Что именно проверялось на настоящем облаке, а что на подмене, написано в конце [docs/SETUP.md](docs/SETUP.md).

## Политика конфиденциальности

Тексты лежат в `js/pages/privacy-text.js` (русский и казахский). Это рабочий шаблон, описывающий именно то, что делает сайт. Перед запуском для широкой публики его стоит показать юристу и поменять адрес поддержки в `js/config.js`.
